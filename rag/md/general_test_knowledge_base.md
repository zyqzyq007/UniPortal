## Python 并发与 GIL

Python 的 GIL（Global Interpreter Lock，全局解释器锁）是 CPython 解释器中的
一把互斥锁，保证同一时刻只有一个线程执行 Python 字节码。对于 CPU 密集型任务，
多线程受 GIL 限制无法真正并行；对于 I/O 密集型任务，线程会在 I/O 阻塞时释放
GIL，因此多线程仍能提升整体吞吐。需要真正并行执行 CPU 密集任务时，可使用
`multiprocessing` 多进程或原生扩展绕开 GIL。

## 网络协议：HTTP 与 HTTPS

HTTP（超文本传输协议）以明文方式传输数据，中间环节可被窃听或篡改。HTTPS 在
HTTP 之下加入 TLS（传输层安全）加密层，通过数字证书验证服务器身份，并对传输
内容进行加密与完整性校验，从而提供机密性、完整性与身份可信。启用 HTTPS 通常
需要向证书颁发机构（CA）申请证书，并在服务器配置 TLS。

## 版本控制：git rebase 与 git merge

`git merge` 会保留两条分支的完整历史并生成一个合并提交，历史真实但可能分叉；
`git rebase` 把当前分支的提交逐个重放到目标分支顶部，得到线性、整洁的历史，
但会改写提交哈希。团队协作中，公共分支（如 main）通常用 merge 保留真相，
个人特性分支整理历史时可用 rebase。对已推送给他人的提交应避免 rebase，以免
历史冲突。

## 容器化：Docker 镜像分层

Docker 镜像由一系列只读层（layer）组成，每条 Dockerfile 指令通常产生一层。
层之间通过联合文件系统（UnionFS）叠加，构成最终的根文件系统。分层的核心
好处是：相同层可在多个镜像间复用，节省存储与拉取时间；构建时按层缓存，未变动
的指令可直接命中缓存，加速构建。容器运行时在镜像之上挂载一层可写层。

## 数据库索引

数据库索引（如 B+ 树索引）把一列或多列的值按序组织，使等值查询与范围查询
能够通过对数复杂度的树结构快速定位，避免全表扫描，从而显著加快读取。索引的
代价在于：占用额外存储空间，且每次插入、更新、删除都需要同步维护索引结构，
带来写入开销。因此写密集场景需权衡索引数量。

## 运维实践：定期备份

对 Linux 服务器进行定期备份的推荐步骤：1) 确定备份范围与策略（全量/增量、
保留周期）；2) 选择工具，如 `rsync`（增量同步）或 `tar`（归档）；3) 编写
备份脚本并结合 `cron` 定时执行；4) 将备份副本传输到异地或对象存储以防单点
故障；5) 定期演练恢复流程，验证备份确实可用。
